## 4. Booking and service management

I recommend a hybrid booking system.

## Customer booking journey

1. Customer visits the service page.
2. Selects a service or package.
3. Chooses instant booking or requests a quotation.
4. Provides required information and selects a date where applicable.
5. Receives a booking reference and confirmation or quotation status.
6. Completes the required payment or deposit.
7. Receives updates and can track the booking in their account.

### Service-specific booking fields

| Service  | Additional booking fields                                |
| -------- | -------------------------------------------------------- |
| Tech     | Device, issue, support type, remote/on-site              |
| Sound    | Venue, event date, equipment, duration                   |
| Catering | Guest count, menu, venue, event date                     |
| Printing | Print format, size, quantity, paper type, uploaded files |
| Art      | Art category, project brief, dimensions                  |
| Cleaning | Property type, size, address, cleaning frequency         |
| Music    | Event type, performance duration, venue                  |
| Fitness  | Training goals, preferred schedule, training format      |

### Booking statuses

Your administration dashboard should recognise:

- New request.
- Awaiting quotation.
- Quotation sent.
- Awaiting payment.
- Confirmed.
- In progress.
- Completed.
- Cancelled.
- Refunded.

You should also be able to assign a booking to a staff member or instructor as the business grows.

### Why this architecture?

It allows the website to function as three connected systems:

1. Public website: Marketing, services, portfolio and customer acquisition.
2. Business application: Bookings, payments, projects, orders and customer accounts.
3. Learning application: Courses, instructors, students and assessments.

All three share one central database and authentication system.
